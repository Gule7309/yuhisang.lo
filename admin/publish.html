CONTENT RELEASE WORKFLOW

Draft → Review → Publish

CMS 儲存現在寫入 cms-staging，不會直接更新正式網站。確認內容後，透過 GitHub Pull Request 提交審核；只有合併到 main 才會觸發 GitHub Pages 發布。

01 / DRAFT

編輯並儲存

在 CMS 中編輯內容並使用雙語即時預覽。Save 將變更存至公開儲存庫的 staging 分支，不會直接上線。

02 / REVIEW

建立審核 PR

點選下方連結，確認 base 為 main、compare 為 cms-staging。檢查全部變更、CI 與公開資訊，再決定是否發布。

03 / PUBLISH

明確合併

核准後合併 PR，GitHub Pages 才會部署。部署後在正式網站與內容檢查中心核對結果。

建立／查看發佈 PR 回 CMS 編輯 查看正式資料檢查
發布前注意：cms-staging 和 PR 仍在公開 GitHub 儲存庫中，不能存放機密草稿、私人資訊、Token 或未授權研究材料。published: false 僅影響網站顯示，並不代表資料私密。這是分支級發布流程，不是每篇內容獨立的審核卡。

發佈清單

  • 在 CMS 確認中文與英文、研究狀態、圖片和來源；不確定的成果不要寫成已驗證。
  • PR 中只能有 content/*.json 既定檔案與 CMS 上傳素材。程式碼、設定檔或工作流程修改應走獨立開發 PR。
  • 執行 CI、確認沒有衝突，完整檢視變更後再合併；CI 不會自動審核內容真實性。
  • 若 PR 提示 staging 落後 main，先保留未發佈內容並將 main 合併回 staging，解決衝突後重新檢查。
  • 合併後再次同步 main → cms-staging，避免下一輪草稿建立在過舊的版本上。不可強制重置有未發佈修改的分支。
這個頁面只提供流程說明與 GitHub 連結，不會讀取 Token、建立 PR、儲存或自動合併任何變更。
